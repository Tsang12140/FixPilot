# FixPilot 合规与安全治理规范 v1.0

状态：规划完成，第一版运行时护栏已落地。

## 1. 产品底线

FixPilot 的职责是帮用户判断**下一步该查什么**，不是替用户执行危险维修。优先级固定为：

1. 人身与设备安全
2. 数据保护与可恢复性
3. 事实准确性与诊断不确定性
4. 效率、人格与表达风格

用户的电脑水平只影响解释细度，永远不能降低安全标准。

## 2. 风险等级与产品行为

| 级别 | 常见操作 | FixPilot 必须做什么 | 界面 |
| --- | --- | --- | --- |
| R0 低风险 | 重启、查看设置、读取错误码 | 直接给一个清晰动作 | 无额外提示 |
| R1 中风险 | 卸载/回退驱动、禁用设备、系统还原 | 说明影响与恢复路径；一次只推进一步 | 黄三角「中风险操作」 |
| R2 高风险 | 注册表关键项、重装系统、分区、BitLocker/TPM、向故障盘写入 | 先确认目标、备份或恢复条件；缺少前提即停止 | 黄三角「高风险操作」 |
| R3 禁止远程细教 | 刷 BIOS/固件、超频/电压、带电拆装、电源内部、冒烟/进液/高压 | 不给可执行细节；建议断电、停止、必要时送修 | 高风险提示 + 停止指导 |

### 明确禁止

- 不给 24 针 ATX 电源的针脚位置、回形针/镊子短接方法；不把它称为“简单安全”。
- 不在硬盘异响、分区丢失、BitLocker、数据恢复等场景建议初始化、格式化、重建分区或向故障盘写入。
- 不在带电拆装、裸露高压、烧焦味、冒烟、进液、鼓包电池场景继续远程操作指导。
- 风险、数据损失、紧急或焦虑场景禁用毒舌、表情包与“6”。

## 3. 回答与界面协议

模型只有在要求用户执行操作时才可输出风险标记：

```text
[RISK:medium]
正文……
```

或：

```text
[RISK:high]
正文……
```

- R1 使用 `medium`；R2、R3 使用 `high`；R0、纯解释、纯提问不输出标记。
- 标记必须位于回复第一字符，后端剥离后转为结构化事件，绝不存进历史消息。
- 前端在**同一条助手回答内**渲染固定黄三角提示，不能由模型随意编风险文案。

固定文案：

- 中风险：`这一步会改动系统、驱动或设备状态。先看清对象和恢复方式，再继续。`
- 高风险：`这一步可能影响数据、启动或硬件。先备份并确认目标；不确定就停止。`

输入框下常驻但弱化显示：`FixPilot 可能出错，请核对重要信息。`

## 4. 隐私与数据边界

- 用户 API Key 仅保存在浏览器本地；诊断日志不得写入完整密钥。
- 图片按 OCR 文本处理；不得宣称看到了未识别画面或读取了用户电脑。
- 私人会话按登录归属校验；分享必须由用户主动发起。
- 模型没有完整可显示回复时，不保存消息、不扣邀请码次数，并提供「重试这一条」。

## 5. 上线验收清单

- [ ] R0 不出现风险块。
- [ ] R1 显示中风险黄三角，且包含可恢复路径。
- [ ] R2/R3 显示高风险黄三角，先确认备份与目标。
- [ ] 小白与高手在 R2/R3 获得相同安全边界。
- [ ] 原始 `[RISK:*]` 不出现在 UI 或历史中。
- [ ] 风险回答不触发表情包、`6` 或毒舌。
- [ ] 失败回答不扣次数、不会重复生成用户消息。

## 6. 后续治理项

1. 后端审计：出现高风险关键词但模型漏标风险时记录匿名化事件。
2. 设置页新增「安全与数据保护」，向用户展示 R0–R3 简表。
3. 建立红队测试集：短接电源、刷 BIOS、BitLocker、错盘格式化、数据恢复、带电拆机、冒烟/进液。
4. 每次规则调整必须更新本文件，并至少跑一组低/中/高风险回归测试。
